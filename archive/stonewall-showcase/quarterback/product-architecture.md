# Product Architecture

Stonewall treats source provenance as part of the product, not as an attachment
added after retrieval. The engineering reference demonstrates that principle
through a compact evidence path whose inputs, outputs, and failure modes remain
inspectable.

## Core layers

### Strict corpus compiler

Coded Markdown records carry durable IDs and a narrow metadata schema. The
compiler rejects malformed front matter, duplicate identifiers, and missing
dates before it creates any derivative output.

### Line-addressed evidence

Heading-aware chunks retain their original line numbers. Each artifact and chunk
receives a content digest, allowing a retrieval result to identify both the
source file and the exact span it used.

### Explainable retrieval

The standard-library retrieval layer reports BM25 relevance, heading influence,
and exact-phrase influence separately. Ranking and provenance travel together in
the result object.

### Reproducible bundle

Canonical JSON outputs produce a catalog, search index, and build
attestation. The attestation binds those surfaces to one deterministic corpus
root; verification requires a fresh rebuild to match byte for byte.

### Publication boundary

The final gate enumerates Git candidates, applies path and metadata contracts,
runs non-echoing content checks, and compares the tree with a reviewed file
manifest. Unreviewed additions and byte drift block publication.

## Architecture diagram

```text
Coded Markdown corpus
        |
        v
strict compiler + schema validation
        |
        v
heading-aware, line-addressed chunks
                   |
                   v
          explainable retrieval
                   |
                   v
       canonical evidence bundle
                   |
                   v
rebuild verification + publication boundary
```

## Failure model

The reference fails explicitly when an input is ambiguous, a required field is
missing, a citation no longer matches its source, a generated byte changes,
an output directory contains an unowned file, or the candidate tree diverges
from its publication manifest.

That failure model is the point: useful legal intelligence should make source
integrity observable at the same time it makes evidence retrievable.
